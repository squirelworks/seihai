Seihai 0.0.6: the Graal client (mae for 1.x/2.x, ato for 3.x, issho for 6.x, g3d for Graal3D) and `seihai-core`, the library the Seihai servers build on. This is the tag the server repos and seihai-servertools move to next.

## New since 0.0.5

**For the servers and tools**
- **`seihai-draw`** (#350): a shared RGBA tile and gani drawing crate, used by seihai-servertools' level and gani editors. This is the first tag that has it, so servertools can stop pinning a commit.
- **`playerleaves`** is a script event from the 2.1 era (#390), so seihai-npcserver's server-side `if (playerleaves)` runs. No client fires it.
- **GS1 to GS2 compiler, first slices** (#376, #381, #383, #384): a restricted GS1 front end on Seihai's own GS2 compiler, validation of operands, references and builtin arity, and array literals. This is a subset; #371 tracks the rest.
- **One listserver host** (#389): `listserver.graal.in` is the only real host Seihai names. The defunct graalonline.com addresses each old build carried are gone from the client (they are history, kept in Graal_analysis). **API change:** `BuiltIn`, `BUILT_IN_14921`, `BUILT_IN_14922` and `Listserver::built_in` are removed, `Listserver::new` takes `(kind, status, token)`, and `ServerList::Direct` has no field.

**Client**
- **Graal3D** (`seihai-g3d`): the client's camera numbers (#357), drawing with no assets folder (#361), its own start window (#363), a "Graal3D" entry in the start window's Version list (#364), and the F1 hardware options and F2 player look (#365).
- **New crate `seihai-issho`** for the 6.x profile (#379). The launcher starts it for 6.x; it is a shell that does not draw yet. 7.x is refused.
- **Ato** compiles its Torque engine scaffold for 3.x to 5.x (#378). Its subsystems are stubs; Ato still draws the level flat in 2D with a local walk.
- Game connections turn Nagle off, so small packets such as movement go out at once (#360).
- Version profiles: 1.39 knockback and respawn (#347), the 1.39 death row (#351), each profile's main-window size (#349), early profiles kept on the documented GS1 fallback (#386), and the first Graal relay-room metadata corrected (#387).

**Quality**
- Every pull request builds and tests on Linux, macOS and Windows (#354), with `cargo fmt` and strict clippy as required steps (#381, #382). Three timing races the new CI found are fixed (#358, #388).
- Ghidra tooling and Ghidra-derived names are gone from the client and its docs (#348, #355); machine-specific details are gone from the docs (#370).
- Releases are drafts that the owner publishes (#359, #362); macOS builds are best effort and never block the draft (#366, #368).

**Docs**
- HUD fonts and per-version UI facts from the client rebuilds (#369), Mae's client and fallback boundaries (#385), the Graal3D milestones (#352), trainer threats and server-side defences (#337), the contributor binding rules (#336), and a staleness refresh of the release table, roadmap and crate paths (#391).

## Known not to work yet

- Ato has no server list, offline mode or post-login frame, and no NPCs, other players or GANI art. Its 3D (Torque) path is held until a capture exists.
- `seihai-issho` does not draw.
- The GS1 to GS2 compiler accepts a subset; anything else is a clear compile error.

## Download

Each archive holds `seihai`, `seihai-mae`, `seihai-ato`, `seihai-issho` and `seihai-g3d`. They come for Linux x86_64 and Windows x86_64. On Linux, sound needs ALSA. Archives for macOS Intel (x86_64) and Apple Silicon (aarch64) are added to this release when GitHub's macOS build machines have room; if they are not here, build from source with `cargo build --release`. On macOS, the first start may need right-click → Open, because the build is not signed.

Start with `seihai` (the launcher). It picks mae, ato, issho or g3d for the client version you choose. Keep the five programs in one folder.
